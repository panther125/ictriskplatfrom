挂真实 design.css。仅展示「试算输入」卡片，其余页面不变。
改动点：
① 预设按钮行行首新增「解析入参」按钮（描边高亮 · 新），点击按当前试算对象（策略 + 版本）自动解析入参；
② 解析 = 策略自定义入参（param.* 引用并集） + 引用到的特征的对应入参（feat.* → 特征入参清单，含 @@ 链与「入参定义」调整）；
③ 回填语义（推荐 A）：以解析结果重建键集，同名键沿用输入框现值，新键补占位值，无关旧键移除——按钮输出即「该策略真正需要的入参清单」；
④ 按钮行下方新增解析结果提示行（数量 / 键名 / 来源 / 告警），不弹窗。
一、初始态新增：解析入参按钮

该版本登记了 8 个决策节点，试算按节点条件真实求值（按优先级短路），命中哪个节点就用它的结论与原因码。
特征侧派生：overdue_cnt → feat.user_overdue_level（H/M/L）、risk_score → feat.risk_level（HIGH/MID/LOW）。debug=true 时强制采样并记录完整 trace。

入参来源（节点引用清单）：user_id / apply_amount / channel ← n_001 开始 START； channel / risk_score ← n_006 交叉决策树； 特征 user_overdue_level ← n_003 特征·逾期等级、n_005 决策·逾期准入

三、提示行的其它形态（示例）特征带出入参 · 未编排 · 告警

a) 引用特征带出入参（示意：临时测试版本引用 feat.dreiver_feature）：

✓ 解析完成 策略入参 2 个：customerId、amount · 引用特征 1 个：dreiver_feature → 2 个入参：a、b
a、b · DECIMAL · 必填 ← 基础特征 demo_pmml_base_feature → 视图 demo_pmml 入参

b) 所选版本未编排决策图（如 loan_apply v11）：

✓ 解析完成 未解析到变量引用
⚠ 该版本未编排决策图，试算会走默认规则集（overdue_cnt ≥ 3 → REJECT · risk_score ≥ 800 → REJECT · 其余 REVIEW）

c) 引用特征存在异常（不存在 / 已下线）：

⚠ 引用特征「user_overdue_cnt」已下线，试算时不会计算它（引用节点：n_00x 特征·逾期次数）
⚠ 引用特征「xxx」在特征表中不存在（引用节点：n_00y 决策·评分），请回编排页检查
四、解析数据来源（零 DDL · 全部复用既有数据）
① 策略自定义入参 = 所选版本决策图节点的引用变量清单 decision_node.ref_vars_json 里 param.* 并集（表达式文本里的 c.* 兼容入内）；
② 引用特征 + 其入参 = 同一清单里 feat.*（兼容 f.*）→ 按编码查特征表 → 复用既有 FeatureService.resolvedInputsOf（自动展开 @@ 链、:param.，叠加「入参定义」的启停 / 类型 / 必填 / 默认值 / 手工补充行）；
不做：view.* 视图入参本次不进模板（后续可扩展）；接口只读不写库、不触发试算。
