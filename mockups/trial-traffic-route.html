四、解析入参与自动模式一致性小改
试算输入POST /trial/resolve-inputs
试算对象 loan_apply · 自动（按切流判定）
✓ 解析完成 ：策略入参 4 个（user_id、apply_amount、channel、risk_score）· 引用特征 1 个（user_overdue_level → 0 个入参）
ⓘ 自动模式：按切流判定本笔将执行 v11（哈希槽位 63），已按该版本引用解析入参。

不做这步的话会出现「输入框键集 = 默认版本，执行 = 命中版本」的错位；做法：resolve-inputs 请求体带当前输入框 JSON，后端走同一判定算法。

五、数据来源与算法口径（零 DDL · 零新端点）
判定数据 = strategy_version（状态 / 份额）+ grayscale_rule（mode / traffic_pct / whitelist_users / channel / user_tag / status）——与「切流配置」弹窗同一份数据，修改切流立即影响试算判定；
特征计算 = 复用 FeatureService.trial（四引擎真实执行）+ resolvedInputsOf（入参解析），出参按「引用名口径」回填 feat.*；引擎失败才回退内置派生并挂 ⚠；
接口 = POST /trial/execute 未带 version_id 即自动判定，响应新增 routing / featureRuns / nodeDetails；无新表、无新端点；
复现口径 = md5(user_id) 前 8 位 % 100 定槽位：U100823 → 63 → v11（70%）· U100003 → 21 → v13（30%）。
已确认决策（2026-10-14 送审通过）：
  • D1 版本选择：保留下拉 + 新增「自动 · 按切流判定」为默认（本稿右侧即为该形态）——手动选具体版本保留，用于定点调试 / 回放。
  • D2 随机切流试算行为：RANDOM / PERCENT 统一按 user_id 哈希固定（可复现，用例回归不抖动；生产 RANDOM 的真随机语义不受影响）。
