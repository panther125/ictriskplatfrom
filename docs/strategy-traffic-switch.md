# 已上线策略「切流」配置（决策级多版本分流）设计说明 · v2

> 需求：已上线的策略添加「切流」按钮，让用户可以配置对应的切流配置。
> 澄清（v2 语义）：**切流对象是「一个决策」，切的是决策内的各版本**——例：随机切流 50% → v0.0.1、50% → v0.0.3。
> 结论：前端（`StrategyManage.jsx`）+ 后端（新增决策级切流接口）改动；**无 DDL**（`grayscale_rule` 现有结构可承载多版本份额，仅同步 init.sql 遗漏的 `mode` 列）。
> 配套 mockup：`mockups/strategy-traffic-switch.html`（挂真实 design.css）。

---

## 一、语义模型

### 1.1 切流配置 = 决策级「版本份额表」

一个决策（策略）下可以有多个版本**同时在线**，各版本按分配的份额分流。配置的对象是整个决策，一次给多个版本分配：

```
随机切流：  v0.0.1 ← 50%      百分比切流：  v11 ← 70%（hash 0–69）
             v0.0.3 ← 50%                    v13 ← 30%（hash 70–99）
```

| 规则 | 说明 |
| --- | --- |
| 合计 | 各版本份额之和**必须 = 100%**（整数），否则阻断保存 |
| 可参与版本 | 状态「已发布 / 已下线」的版本 |
| 不可参与 | 「草稿 / 待审」版本（灰显置底，提示「未发布，不可参与切流」） |
| 活跃版本上限 | 同时承接流量的版本 ≤ 5 个（沿用 `docs/04-decision.md` §11.3 灰度约束） |
| 决策级字段 | 切流方式 / 限定渠道 / 客群标签对决策下所有参与版本统一生效 |
| 份额为 0 | 在线版本填 0 = 保存后自动下线，从份额表移除 |
| 复活已下线 | 已下线版本填 >0 份额 = **重新上线**（等价回滚到该版本，与 §11.1「回滚 = 指针切换」一致） |

### 1.2 三种切流方式（决策级）

| 方式 | 分配规则 |
| --- | --- |
| 随机切流 `RANDOM` | 不区分用户，每笔请求按份额随机分配（快速放量观察） |
| 百分比切流 `PERCENT` | `hash(bizKey) % 100` 落在哪个份额区间就命中哪个版本，**同一 bizKey 固定命中同一版本，不抖动** |
| 白名单切流 `WHITELIST` | 白名单用户固定命中对应版本；未命中白名单的流量走「兜底版本」（单选框，必选） |

百分比模式的份额区间按弹窗行序累积并**直接展示**（`hash 0–69` / `70–99`），配置即所见，审计友好。

### 1.3 份额 → 版本状态的归一（保存后）

| 份额 | 版本状态 | state_label | grayscale_pct | 灰度规则 |
| --- | --- | --- | --- | --- |
| 100% | `PUBLISHED` | 生产运行中 | 100 | ACTIVE，traffic_pct=100 |
| 1–99% | `GRAYSCALE` | 灰度中 X% | X | ACTIVE，traffic_pct=X |
| 0%（原先在线） | `ROLLED_BACK` | 已下线 | 0 | INACTIVE，traffic_pct=0 |
| 草稿/待审 | 不动 | 不动 | 不动 | 不动 |

- 灰度规则继续存在 `grayscale_rule`（每版本一行），决策级字段（mode / channel / user_tag）**由本接口统一写入多行**，保持一致。
- 白名单模式：兜底版本 traffic_pct=100（`PUBLISHED`）；被白名单命中的版本状态 `GRAYSCALE`、state_label「白名单 N 人」、whitelist_users=N。
- 与既有状态口径完全兼容：`StrategyStatus.isPublished()` 覆盖 `PUBLISHED / GRAYSCALE`，版本三态展示不变。

## 二、入口与交互

### 2.1 两个入口，同一个弹窗

| 入口 | 位置 | 显示条件 |
| --- | --- | --- |
| 列表行「切流」 | 策略列表操作列，追加在「版本 / 编排」之后 | 仅 `status = 已发布` 的策略（有在线版本）；草稿策略不显示 |
| 版本卡「切流」 | 右侧版本列表，替换原「流量分配」按钮 | 展开任一策略即可（对应版本行预高亮） |

点击 → 拉 `GET /api/strategies/{id}/versions`（按钮短暂 loading）→ 打开「切流配置 · {策略名}」弹窗，预填当前各版本的份额 / 切流方式 / 渠道客群。

### 2.2 弹窗结构（宽 660）

```
┌ 切流配置 · 还款能力准入策略          PUT /api/strategies/1/traffic ┐
│ 上下文：该决策下有 3 个版本，合计需等于 100%……                        │
│ 切流方式   [随机切流] [百分比切流✓] [白名单切流]  + 方式说明            │
│ 版本份额   版本 | 状态 | 份额区间(或白名单人数/兜底) | 放量比例 %        │
│            v13 | 已发布 | hash 0–29   | [30]                        │
│            v11 | 已发布 | hash 30–99  | [70]                        │
│            v12 | 草稿   |     未发布，不可参与切流                     │
│            当前 2 个版本承接流量（上限 5 个）   ✓ 合计 100%            │
│ 限定渠道 [____]        限定客群标签 [____]                           │
│                                        [取消] [保存切流配置]          │
└──────────────────────────────────────────────────────────────────┘
```

| 状态 | 交互 |
| --- | --- |
| 合计 = 100% | 绿色 ✓ 徽标，保存可用 |
| 合计 ≠ 100% | 红色徽标「合计 90%，还差 10%」+ 红字说明，**保存按钮禁用** |
| 版本行排序 | 已发布（新→旧）→ 已下线 → 草稿/待审 |
| 草稿/待审行 | 灰显、份额输入禁用、提示「未发布，不可参与切流」 |
| 白名单模式 | 表头换成「白名单人数 / 兜底」两列；校验至少 1 个版本白名单人数 >0 且必选兜底 |
| 保存成功 | 关闭弹窗，刷新列表（线上版本 / 流量列）+ 右侧版本卡 |

### 2.3 列表列改动

| 列 | 现状 | 改后 |
| --- | --- | --- |
| 状态 | 已发布 / 草稿（StatusTag） | **删除**（实现时按用户要求移除；顶端筛选 Tab 与右侧详情卡仍保留状态展示） |
| 线上版本 | `v11`（单版本） | `v11、v13`（多版本顿号拼接） |
| 流量 | `100%` | `70% / 30%`（与线上版本同序一一对应） |

## 三、接口设计

### 3.1 新增：决策级切流配置

```
PUT /api/strategies/{strategyId}/traffic
```

```json
{
  "mode": "PERCENT",
  "channel": null,
  "userTag": null,
  "shares": [
    { "versionId": 13, "trafficPct": 30, "whitelistUsers": 0, "fallback": false },
    { "versionId": 11, "trafficPct": 70, "whitelistUsers": 0, "fallback": false }
  ]
}
```

服务端校验（全部为友好 400）：

| 校验 | 提示 |
| --- | --- |
| 策略存在、版本都属于该策略 | `版本不属于该策略` |
| 参与版本状态 ∈ {已发布, 已下线} | `版本 v12 尚未发布，不能参与切流` |
| 份额为 0–100 整数 | `份额需为 0-100 的整数` |
| 合计 = 100（RANDOM/PERCENT） | `各版本份额之和必须等于 100%（当前 90%）` |
| 活跃版本 ≤ 5 | `同时承接流量的版本最多 5 个` |
| 白名单：恰 1 个兜底 | `白名单切流需选择且仅选择一个兜底版本` |
| 白名单：至少 1 个 >0 人数 | `白名单切流至少为一个版本配置白名单人数` |

保存动作（事务）：逐版本 upsert `grayscale_rule` + 归一版本状态（§1.3）；一次保存同时完成上线 / 下线 / 复活三类变更。

### 3.2 移除：单版本切流接口

`PUT /api/strategies/versions/{versionId}/traffic` **删除**（单版本口径与「合计 = 100%」冲突，保留会绕出不一致数据）。前端 `api.strategies.updateTraffic` 同步替换为 `updateStrategyTraffic(strategyId, body)`。

### 3.3 列表接口扩展

`GET /api/strategies` 的 `StrategyItemDTO`：

- `onlineVersionNo` / `onlineTrafficPct`（单版本字段）→ 替换为 `onlineVersions: [{versionNo, trafficPct}]`；
- 排序 = 在线版本按份额行序（新→旧）；空数组 = 未上线（status 仍为 DRAFT）。
- `GET /{strategyId}/versions` 不变（版本卡展示继续用现有 `trafficMode / trafficPct / whitelistUsers` 字段）。

## 四、与现有操作的关系

| 操作 | 变化 |
| --- | --- |
| 发布（版本卡） | **语义不变**：全量切到该版本（100%），同策略其它在线版本下线、灰度规则失效——即会清空已有的多版本切流。发布确认文案补充提示「将清除该策略现有的切流分配」。 |
| 下线（版本卡） | 保留：下线单个版本、对应规则失效、份额清 0。若该版本原在切流份额表中，下线后合计可能 <100，属配置中间态；再次保存切流时强制配平。 |
| 回滚 | 不再需要单独入口：已下线版本在切流弹窗里填 >0 份额即重新上线（等价于指针切回）。 |
| 试算 / 编排 / 监控 | 不受影响（读到的仍是 `strategy_version` 与 `grayscale_rule` 现有字段）。 |

典型动作串联：`v11 100%` → 发布 `v13`（全量 v13、v11 已下线）→ 切流配 `v13 30% / v11 70%`（v11 复活）→ 观察后改 `v13 70% / v11 30%` → 全量 `v13 100%`（v11 自动下线）。

## 五、边界（本次不做）

- **运行时路由接线**：按份额选版本执行的引擎侧逻辑不在本次范围，与现状一样先交付配置能力（存量「流量分配」同样只是配置态）。
- 不做份额小数、不做灰度自动推进 / 自动回滚（§11.3 的 P1 项）。
- 不在编排页 / 监控页加切流入口。
